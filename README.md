## Описание

Автономна система за мониторинг и алгоритмично търгуване на криптовалута, работеща непрекъснато в облачна среда. На всеки четири часа системата анализира пазара чрез седем независими източника на информация, обединява ги в претеглен сигнал и при достатъчна увереност изпълнява реална сделка на демонстрационна борсова сметка.

## Аналитични слоеве

| Слой | Източник | Тежест |
|---|---|---|
| Мултитаймфрейм технически анализ | TradingView (1ч, 4ч, дневен) | ±4 точки |
| Индекс на страха и алчността | alternative.me | ±3 точки |
| Прогноза от машинно обучение | XGBoost + невронна мрежа (MLP) | ±2 точки |
| Анализ на новинарския поток | RSS: CoinDesk, CoinTelegraph | ±2 точки |
| Блокчейн метрики | blockchain.info | ±1 точка |
| Дълбочина на пазара | Bybit order book | ±1 точка |
| Активност на едри участници | Blockchair | предпазен филтър |

Върху агрегирания резултат се прилага тренд филтър, който блокира сделки срещу основната пазарна посока.

## Управление на риска

- Стоп-загуба: −5 %
- Фиксиране на печалба: +6 %
- Плъзгаща се стоп-загуба: активира се при +4 %, дистанция 3 %
- Размер на позицията: 50 % от баланса
- Сделка се отваря само при силен сигнал (≥ 5 точки)

Параметрите са оптимизирани чрез мрежово търсене върху 108 комбинации и петгодишен исторически период.

## Конфигуриране

Преди стартиране е необходимо да се попълнят следните параметри в началото на `bot.py`:

| Параметър | Как се получава |
|---|---|
| `TELEGRAM_TOKEN` | @BotFather в Telegram |
| `TELEGRAM_CHAT_ID` | `api.telegram.org/bot<TOKEN>/getUpdates` |
| `SHEET_ID` | от адреса на Google таблицата |
| `GOOGLE_CREDENTIALS` | служебен акаунт в Google Cloud (JSON) |
| `BYBIT_API_KEY` / `BYBIT_API_SECRET` | Bybit → Demo Trading → API (права Read-Write) |

Google таблицата трябва да бъде споделена с адреса `client_email` от служебния акаунт.

Инсталиране и стартиране:

```bash
pip install -r requirements.txt
python bot.py
```

## Забележка относно сигурността

Настоящото хранилище съдържа единствено заместващи стойности на ключовете за достъп.
Реалните идентификационни данни не се съхраняват в програмния код. При производствено
разгръщане те се задават като променливи на средата на хостинг платформата.

## Ограничения

- Системата работи с демонстрационни средства; не е предназначена за търговия с реален капитал.
- Оптимизацията на параметрите е извършена върху същия исторически период, върху който е и оценена, поради което съществува риск от свръхнагаждане. Валидацията продължава чрез форуърд тестване в реално време.
- Обратното тестване обхваща четири от седемте аналитични слоя — останалите нямат публично достъпни исторически данни.
